## 注意点（間違えやすいところ）

- **「差分更新に4時間」は誤り。**4時間は商品マスタ全件更新（約40万件）の実測値。
  差分更新の問題は時間ではなく「どの行が変わったか判別できない」こと
- **goods_csアプリの洗い替え所要時間は未測定。**担当者向けの文面でも時間には触れていない
- **Coworkのファイル連携:** セッション開始時にTドライブのフォルダを接続し忘れない。
  PC上のシェル（device_bash）で読み書き・git可。**Tドライブへの stage／commit は失敗する**（fetch or write failed）。
  クラウドで作ったファイルは **ダウンロードフォルダ（C:）へ commit → device_bash で T へ cp** で渡せる
  **同じ名前で2回目以降に渡すと、古い中身が届くことがある** → 毎回別名で渡し、cp前に grep で中身を確認する
- **git:** Cowork側では push できない。コミットしたらユーザーに push を促す。
  `.git` にロックファイルが残る（削除できないため `*.claude-stale` に rename して退避している）
- **kintoneの読み取り:** ChromeからREST API（GETのみ、`X-Requested-With` ヘッダ付き fetch）。
  データをPCへ渡すときは、ページ内でJSONを作ってダウンロードさせる。
  出力にURLのクエリ文字列や `key=value` が含まれるとツール側でブロックされる
- kintone: `https://zrqf50naoiwx.cybozu.com`。商品マスタ＝51、子カテゴリマスタ＝44、
  在庫＝64、在庫分析＝65、旭川在庫管理＝69、月末在庫報告書出力＝73、goods_csテスト＝93。
  JSは各アプリのmain.jsのほか、**全体カスタマイズの共通4ファイル**（config.js / KintoneAPIFunctions.js /
  GoogleAPIFunctions.js / ui.js）を使う。config.js はトークン入りなので伏せて保存済み
- **`fetchRecordsFromApp()` はビューの `filterCond` を読んで query に使う。**
  つまり「ビューを指定して抽出」が成立している。ビューの絞り込み条件を変えれば、
  そのビューを見ているJS全部の取得結果が変わる
- VBAのkintone接続情報は `260318ー登録エクセルkintone化\納品書作成\config\kintone_config.xlsx`。
  各xlsmの「設定」シート A2 にそのパスが入っている
- **kintoneの一括削除は5万件/回。連続投入は空振りする**（キューに入らず「0件削除」が返る）。
  1回ずつ完了を待って実行する。**対照的にCSV取り込みは複数ファイルをまとめて投入でき、放置できる**
- **テスト用アプリ `goods_cs` = アプリID 93。**CSVから自動生成したあとフィールド型を手修正済み。
  40万件を入れて全削除したので現在は空。再測定に使える
- goods_csの「販売開始日」はセール適用で書き換わるが、セール終了では変わらない → 更新日の代わりにならない
- goods_csのキーは商品展開ID（CS別品番はZOZO上で変わる）。「子カテゴリ」列は名前（コードではない）。
  `使ったデータ\goods_cs_正.csv` は加工済み
- **旧システムの入力は `使ったデータ\`、キントーンの取込元は `元データ-kintone取込\`。**
- **セール業務とフォロー業務で旧システムの絞り込みが違う**（フォローは在庫0も出力）
- 列見出しは改行を含む（`在庫\n数量` など）
- **`claude\` 側（プロジェクト）の更新はTドライブ側に自動反映されない。**手動同期が必要
- **Windows側で削除してほしいもの:** `JS\kintone\kintone_common_js_20260911.json`（トークン入り・git対象外）、
  `JS\kintone\kintone_app44_子カテゴリマスタ.json`（未追跡）、`JS\_to_delete_誤出力_000\`、
  `.git` 内の `*.claude-stale`、ダウンロードフォルダの `*.tmp`（うち `5c504741-….tmp` はトークン入り）・
  受け渡しに使った md 3つ、`split\260901goods_cs_アプリ作成用_ヘッダ＋5行.csv`
