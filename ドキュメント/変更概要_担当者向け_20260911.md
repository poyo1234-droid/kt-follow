# 変更概要（担当者様向け）下書き 2026-09-11

**件名:** 商品マスタの運用変更（案）のご説明とご確認のお願い

---

お疲れさまです。

キントーンの商品マスタについて、運用の変更を検討しています。
まだ案の段階ですが、セール・フォロー・精算の各業務に関わるため、先に概要をお知らせします。
ご意見と、下記「ご確認のお願い」へのご回答をいただけますと助かります。

## 1. なぜ変えるのか

- ZOZOの商品データ（goods_cs）の内容で商品マスタを更新すると、**毎回約4時間**かかります
- 一方で、更新しないままにしておくと、ZOZO側でCS品番やブランド品番が変わった商品が、キントーン上で正しく引けなくなります（9/1〜9/7の6日間で、CS品番が変わった商品が17件、ブランド品番が変わった商品が170件ありました）
- 引けないと、次のような影響が出ます
  - **精算書**: メーカーや掛率が正しく付かず、**精算金額がずれる**
  - **フォロー・セール**: その商品の在庫数や販売数が付かない
  - **返却・旭川在庫**: メーカー名が空欄になる

## 2. 何が変わるのか（案）

| | 今 | 変更後（案） |
|---|---|---|
| 商品マスタ | ZOZOの内容でも更新する | **商品登録のときの情報を持つ場所**にする。ZOZOの内容では更新しない |
| ZOZO側で変わる情報（CS品番・ブランド品番・価格・カテゴリなど） | 商品マスタに入れる | 新しく作る「**goods_csアプリ**」に入れる |
| 商品マスタの全件更新（約4時間） | ZOZOの内容に合わせるには必要（9/1以降は更新していない） | **不要** |

- goods_csアプリは、**毎朝1回、前日までの中身をすべて消してZOZOの最新データを入れ直します**（洗い替え）。業務で使わない「商品コメント」列は取り込みません
- 各業務の画面は、商品マスタとgoods_csアプリの両方を見て、今のCS品番で正しく商品をたどれるようにします（改修はエンジニアに相談中です）
- 精算書は、売上発送データに入っているカテゴリ名から、掛率・精算区分を直接決めるようにします。**商品マスタで見つからない商品があっても、売上発送の精算金額はずれなくなります**
- 元品番は、これまでどおり商品マスタから出します

## 3. 皆さまの作業で増えること（案）

1. **毎朝1回、goods_csアプリの入れ替え（約30分）**
   - 前日までの中身をすべて削除したうえで、ZOZOから書き出したデータ（4ファイル）を取り込みます
   - 40万件で実際に測ったところ、**削除3〜5分＋取込26分で約30分**でした。画面での操作が続くのは削除の3〜5分だけで、取込はまとめて投げれば席を立てます
   - セール・フォロー・精算の業務ごとに都度回すのではなく、**朝にまとめて1回**とします
   - 入れ替えの最中はデータが途中の状態になります。**「更新中」「更新完了」を社内にご案内いただきたい**です
2. **新しく登録した商品の「商品展開ID」を入れる**
   - 商品展開IDは、ZOZOに登録した後に決まる番号です。CS品番が変わっても変わらないため、商品をたどる手がかりにします
   - ZOZO登録後に、ZOZOから書き出したデータを取り込んで埋める方法を考えています。手順はこれから決めます

## 4. ご確認のお願い

1. 業務の前にgoods_csアプリへの取込を行う運用で、差し支えないでしょうか。業務の流れの中で、取込を入れやすいタイミングがあれば教えてください
2. 商品展開IDの入力は、どなたが、どのタイミングで行うのがよいでしょうか（商品登録の担当の方を想定しています）
3. 商品マスタの「**販売状況**」（販売中など）は、現在どなたが、どのように更新されていますか？ フォロー・セール・旭川在庫の対象商品を、この項目で絞り込んでいます
4. 追加納品の納品書を作るとき、CS品番はどこから入力されていますか？（ZOZOの画面、ZOZOから書き出したCSV、キントーンなど）
5. 印刷した納品書に「上代（税抜）」「上代合計」の欄は載っていますか？
6. 9/11には「各業務の前に取込」でご了承をいただきましたが、実測の結果、**朝1回にまとめて約30分**で回す形に変えたいと考えています。この運用で差し支えないでしょうか。また、この入れ替え作業はどなたが担当されるのがよいでしょうか

以上、よろしくお願いいたします。
