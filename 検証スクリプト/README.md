# 検証スクリプト

キントーンが出力したフォローリストと、旧システムの出力を突き合わせる。

## 使い方

```bash
cd 検証スクリプト

python フォローリスト突合.py            # キントーン側に出力がある全メーカー
python フォローリスト突合.py 2          # メーカーNo. で絞る
python フォローリスト突合.py 2 9 51
```

必要なもの: Python 3 と `openpyxl`。

## 見方

- **共通 / キントーンのみ / 旧のみ** … CS別品番での行の突合結果。
  現時点ではキントーン側に「メーカー在庫切れSKU」の除外が入っていないため、
  「キントーンのみ」が大きく出る（メーカー2で2,463件）。Viewの絞り込みが実装されれば0に近づく
- **列ごとの不一致件数** … ヘッダー名が一致する列だけを比較している。
  数値は数値として比較する（旧データ側に `"1000.0"` 形式が混ざるため、文字列比較だと全件不一致になる）

## ファイル

| ファイル | 内容 |
|---|---|
| `フォローリスト突合.py` | キントーン出力と旧システム出力をCS別品番で突合し、列ごとの不一致件数を出す |

## 対象フォルダ

リポジトリ直下からの相対で解決している。

- キントーン: `0907フォローデータ提出用\0907フォローデータ提出用\フォローリスト-kintone出力\`
- 旧システム: `0907フォローデータ提出用\0907フォローデータ提出用\フォローリスト20260907\`

回が変わったらスクリプト冒頭の `KINTONE_DIR` / `KYUU_DIR` を直す。

## 注意

- 旧システム側は1メーカーが子カテゴリ単位で複数ファイルに分かれることがある
  （`00009-…ガレージ様-Abanicos.xlsx` など）。同じメーカーNo. のファイルはまとめて読み、
  CS別品番が重複した場合は最初のものを採る
- 列見出しは改行を含む（`在庫\n数量` など）。表示するときだけ改行を除いている
- **比較前に NFKC 正規化をかけている**（全角・半角の揺れを吸収するため）。
  そのため件数が `ドキュメント\突合結果_20260909_メーカー2.md` と一部ずれる。
  同書は生値のまま比較しており、商品名は608件。本スクリプトでは正規化で6件が解消して602件になる。
  JANコードも数値として比較するため、同書の38件（末尾".0"の型差）は0件になる
